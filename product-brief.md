# Dimnote

Plugin identity:
- displayName: Dimnote
- description: Adds architectural dimension annotations with extension lines, tick marks, and configurable units/scale to selected layers

Original user prompt:
Can you make me a plugin that will be able to do this for any drawing on the canvas? Preferrably in set ratio and units

Usage:
- Annotation action groups use intrinsic widths and spacing only between groups. The first/last icon-button borders align exactly with the heading/helper's left/right edges (16px and 304px in the 320px panel), with unchanged secondary icon styling.
- Reset appearance sits above Update appearance of all, both full-width secondary buttons with an 8px gap and single-line labels at the unchanged 320px panel width. Update applies current Appearance settings to this plugin's horizontal/vertical, gap/freeform, angled, and radius annotations nested on the page captured at click time, without requiring or changing selection. Units, scale, measured spans, sides, target links, root transforms/sizes, and removed shared extension lines are retained; targets are not regenerated. Content may overflow the unchanged annotation bounds as line distance, gap, or text size changes. Radius endpoints remain filled triangles.
- Page-wide styling loads existing label fonts (including mixed ranges) and the requested Regular face before editing each annotation. Locked/instance boundaries, unsupported legacy group roots (whose bounds cannot be independently preserved), and annotations moved off the captured page are skipped. Invalid/unsupported edited geometry or unavailable fonts are reported as failed or partial alongside updated/skipped counts; unexpected write failures can leave that annotation partially styled. Page changes stop further work and concurrent annotation actions are guarded. Pending resize-label writes are revision-guarded; completed appearance writes baseline the annotation's own pose without detaching ownership. Existing relaunch data and document settings memory are retained. No cross-page scan or target rebuilding occurs. New linear edges/radius annotations save the exact measured span. Legacy axis-a lines are upgraded from their actual current mainline geometry, ignoring stale labels and potentially corrupted measuredSpan/measurement references; radius behavior is unchanged.
- All six i tooltips keep their exact content and zero-delay hover/leave behavior, without click-to-toggle or forced-open state. All triggers are named keyboard-focusable native buttons with identical rest/hover/active styling and a focus-visible outline. PropsKit's real render() creates a portaled dialog > span; only these six popup dialogs receive info-tooltip-popup, removing the built-in span's two-line clamp, 2.5rem height cap and hidden overflow. The scoped popup width is capped at 288px and the iframe width minus 16px; native PropsKit viewport flipping/clamping and accessible descriptions are retained. Color pickers and other tooltips are untouched.
- Browser regression: run `bash test-plugin.sh` with `PROPSKIT_ASSET_DIR` pointing to downloaded real PropsKit assets named `propskit-fig.js` and `propskit-fig.css` (from https://www.figma.com/propskit/fig.js and https://www.figma.com/propskit/fig.css), and `PLAYWRIGHT_MODULE` pointing to an installed Playwright module. `CHROMIUM_PATH` defaults to `/usr/bin/chromium`. Without the asset/module variables this browser test explicitly skips; other regressions and the production build still run. Chromium checks all six exact texts and every glyph's bounds at 320px width / 120, 320 and 900px heights, beyond-two-line endpoint text, identical rest/hover styling, immediate leave and rapid enter/leave cancellation, accessible descriptions/focus/Escape, and full-width single-line stacked buttons. Browser validation uses real PropsKit, not a control shim; it does not run the plugin inside Figma or alter the canvas.
- Annotation entry remains the existing five secondary icon buttons with unchanged styling and one-click behavior for both selected layers and no-selection freeform creation. The heading is "Annotate selected layers" with no selection, "Annotate <layer name>" for one selected layer, and "Annotate <count> layers" for multiple layers. The helper reads "Select layers, then click a side to add." An i tooltip beside that helper explains that clicking an annotation button without a selected layer adds a freeform annotation that can be moved and resized; there is no persistent note below the sections. No separate freeform section, mode, or Generate step is added.
- Select one or more layers, configure units, scale, decimals, and appearance, then use one of five icon actions: Auto adds every distinct outline side of supported irregular straight vector polygons, radius for circles, or width/height otherwise; Top/Bottom add overall local width only; Left/Right add overall local height only (circles retain radius actions). No new controls, angle mode, overall mode, or offset mode.
- Auto replaces existing annotations on either side before recalculating placement; manual positions replace only that chosen side
- Creates a grouped set of dimension lines, extension lines, 45-degree tick marks, and dimension text for each selected layer
- Supports batch annotation of multiple layers at once
- Horizontal and vertical gap annotations require a finite gap greater than 0.0001px and a nonzero measurement after applying scale and the configured decimal precision. Contact, overlaps, floating-point residue, and gaps displayed as zero are omitted; meaningful subpixel gaps remain supported. Zero-sized layer measurements are unchanged.
- Gap measurements use canvas-axis bounding-box separation in one page coordinate space, including staggered/diagonal pairs, nested or differently parented layers, ancestor rotations/reflections/scales, and circles. Auto considers both positive axes; Top/Bottom create horizontal gaps and Left/Right create vertical gaps. Gaps are projected axis distances, not shortest outline-to-outline or Euclidean distances. Overlaps/contact and distances rounded to zero remain omitted.
- New gap annotations use each pair's deepest safe shared editable frame/group/container, never an arbitrary selected target's parent. Canvas-axis measurement and page-space appearance are preserved with inverse absolute transforms (group children use their containing frame/page coordinates); auto-layout overlays are absolute before applying transforms. Locked/instance boundaries and singular, ill-conditioned, nonfinite or host-rejected transforms are bypassed for the next safe shared ancestor, falling back to the page only when none is usable. Sorted target-pair IDs, axis/side, and witness-extension lengths are retained. Reruns find nested owned gaps and replace only selected pairs' requested slots, including old page-level outputs, without deleting another selection's dimensions or unowned legacy/freeform annotations. Staggered witness lengths survive Update appearance of all. Shared-edge cleanup remains parent-scoped. Gaps remain static when either target changes; re-annotate explicitly to recompute spacing/witnesses or omit a now-contacting/overlapping/rounded-zero gap. Independently moved gaps lose pair ownership and survive later pair actions.
- Width and height annotations measure local side lengths and inherit the target's rotation when created. Permanent annotations do not follow later target movement, rotation or resizing. Re-annotate to replace eligible owned slots with current measurements; resize an annotation itself to update its own label.
- In Auto, aligned bounds-based selections with the same height share one vertical dimension on the clearer outer side. Selections containing perimeter polygons or circles do not suppress individual measurements.
- This existing shared-height behavior is regression-tested through the production action for all 24 selection orders of the four touching rectangular VECTORs at y=228, height=80, x/width=149/120, 269/120, 389/120 and 509/180 in parent 185:3892. At scale 0.5, m, decimals 0, clean ownership yields one right-side 40 m height and separate 60/60/60/90 m widths. Auto removes old eligible owned heights on either side and remains stable on rerun; independently moved/freeform history survives until explicitly removed by the user. Left/Right remain per-layer. These are simulated API tests, not live metadata inspection or a new placement feature.
- Auto also shares one bottom width for touching, nonoverlapping vertical chains of selected native rectangles or axis-aligned rectangular VECTOR boundaries with exactly the same x/width and parent. Each chain's bottommost rectangle owns the width; individual heights and existing independent shared-height rules are unchanged. Relative rotations/flips/scales/shears, other shapes, gaps, overlaps, shifted intervals and different parents do not establish sharing. Explicit Auto clears eligible owned H slots for chain members, preserving moved freeforms and unrelated annotations; directional actions remain per-layer. No new metadata, target-follow behavior or shared-line repair is added.
- In irregular multi-selection layouts, Auto places each annotation outward from the selection center and only merges extension lines that truly share the same track
- Auto on one closed simple straight-edged VECTOR boundary annotates all geometric sides, including axis-aligned sides, without extra bounding dimensions. Connectivity orders the boundary independently of segment storage or direction. Connected forward-collinear subdivisions merge across the storage seam; shallow real corners remain separate. Vertex cornerRadius metadata does not add arc measurements: extensions reference underlying geometric joins, with the existing 2px witness gap. Four-right-angle vector rectangles retain the existing bounds behavior, as do native rectangles. Native POLYGON/STAR and arbitrary curve inference are not added; unsupported node types retain bounds.
- Winding in parent coordinates determines each side's local exterior for convex/concave outlines, including target rotations and reflections, without a center assumption. Canonical side direction keeps labels upright in that coordinate space. Relative transforms determine measured endpoints and exact spans. Open, curved, branched, disconnected/multiple boundaries or regions/loops, self-intersections/touching nonadjacent sides, zero-length edges, nonfinite geometry, singular transforms, reversals and zero-area polygons safely use bounds rather than fabricated curve/perimeter lengths.
- Perimeter annotations reuse createHDimFrame in an edge-local rotated frame for sloped/horizontal sides and createVDimFrame for vertical sides. The measured root axis equals the exact edge length; normal depth, line-frame and endpoint constraints are the same as rectangle dimensions. There are no monolithic SCALE-constrained axis-a vectors for new perimeter output. Native fonts, line colors/weight, Slash/Arrow/Triangle semantics and sibling absolute overlays in auto-layout containers are retained. Short spans are never enlarged. Font-loaded text bounds drive conservative parent-space clearance against the polygon and previously placed labels, using the linear builder's actual label-center distance. At most 17 candidates are tried per edge, normally spaced fontSize + 8px; the final candidate also escapes the polygon's support plane when a deep notch requires it. Candidates with dimension lines or text boxes inside/intersecting the polygon are rejected. The first clear candidate (or exterior candidate with fewest label conflicts) wins. This is bounded placement, not a global packing guarantee: dense outlines or neighboring layers/other targets can still conflict. Deep notches may require long extensions across the shape; neighboring-layer/manual-annotation avoidance is not implemented.
- Each side stores a geometric perimeterEdge key plus measuredSpan and clearanceExtra. Explicit Auto replaces the remaining eligible owned perimeter and previous owned bounding/longest sets, including obsolete edges after topology changes/fallback. Directional actions only replace their requested H/V slot and never sweep perimeter edges. Independently moved dimensions permanently become freeform and survive Auto; unrelated manual output is untouched. Target edits never redraw annotations. Own resizing continues to update the local measurement label. Bulk Update appearance retains root identity, size/pose, ownership, side key, exact length and witness starts; it changes appearance in place, preserving each edge's saved extra clearance rather than rerunning target geometry or packing. Large later style changes can still introduce crowding.
- Captured VECTOR 153:3185 / Rectangle55 is covered by actual production action/builder tests: 100 by 150, parent translation (1336,172), rounded vertex metadata, unsorted segments and loop [0,1,4,3,2]. Auto creates exactly five annotations with underlying lengths 118.4577983925077, 86.5, 48.5, 74.62070758174302 and 96. At defaults these read 118.5, 86.5, 48.5, 74.6 and 96 mm. The subdivided 146 by 178 triangle now has exactly three side dimensions (approximately 230.217, 178 and 146px), not a diagonal plus bounds. Acute/obtuse, convex/concave, winding/storage, transforms, short spans, rectangle/fallback, migration, directional/rerun, static/freeform, own resize and bulk-style cases execute production orchestration. A 40-edge topology fixture checks unique edge slots, all five units/precision levels and replacement with a triangle. With PLAYWRIGHT_MODULE set, the suite also writes /tmp/opencode/architectural-perimeter-fixtures.html, architectural-perimeter-fixtures.png and architectural-perimeter-0.svg through -4.svg from production geometry. These are labeled browser simulations using mock font metrics and straight geometric joins, not Figma screenshots or real corner-arc rendering.
- The last-used params are remembered once per document and are never restored from individual shapes
- Font size defaults/resets to 14px and Label gap to 10px, matching the initial UI and missing/invalid-value fallbacks; explicitly saved document settings remain unchanged.
- Line and font colors default/reset to #999999 (opaque); explicitly saved colors and alpha remain unchanged on update. Hex entry accepts six or eight digits with or without #, preserves opacity when six digits are entered, and persists only valid committed colors. Partial/invalid drafts never become black or replace the last valid color; selection/action feedback leaves focused color text and its caret alone. Native/JS picker commits still update colors.
- The panel is 320px wide with a 112px label column so Line distance and its tooltip fit on one line while controls retain useful width and the 300px picker fits.
- Decimals is under Appearance > Labels, after Font size and before Font color, retaining its saved setting and 0-4 range. It sets maximum precision: all dimension labels (including angled, radius, gap/blank, and annotation-resize labels) and the temporary size badge round to that precision, omit unnecessary trailing zeros and whole-number decimal parts, and never show negative zero. Radius labels retain the R prefix and measurements retain nonbreaking unit gaps.
- While the plugin is open, a selected layer shows a temporary real-unit width × height badge that follows resizing and disappears on deselection
- The temporary badge stays horizontal at page level, including within rotated or flipped ancestors, and displays the target's actual width and height scaled to the configured units; permanent annotations remain unchanged.
- Temporary badge cleanup reconciles selection, target deletion, page changes, and restored/cloned tagged badges every 250 ms alongside zoom updates. Badge subtrees cannot become measurement targets. Pending font work is revision/page/selection guarded; render failures and plugin close remove partial or stale badges on touched loaded pages without loading the whole document. Page changes rebind the page-local annotation resize/move observer. Permanent annotations never rebuild in response to layer edits, and resize-label updates never change selection.
- Before publishing, run `bash test-plugin.sh` to execute focused color-entry/persistence/layout, geometry, badge lifecycle, actual page-wide appearance handler/builder, and static-annotation regressions, followed by a production build. Observer tests execute production callbacks with page events and delayed fonts. They verify static annotations after layer edits; explicit side/pair replacement; moved annotations surviving reruns; own resize labels; distinct native-constraint resize and K child/font scaling models; consecutive/nonuniform scales; common-parent motion/grouping; saved/legacy baselines; appearance ownership; page/close cancellation; target deletion; boundaries and selection. Browser tests use real PropsKit in Chromium; these mocks/browser checks do not replace a Figma on-canvas rendering check.
- Short width/height annotations preserve the measured span rather than imposing a 28px minimum. Labels remain single-line and centered on that span, overflowing the unclipped annotation frame when necessary.
- Every label builder/write explicitly restores WIDTH_AND_HEIGHT, disables truncation and clears maxLines before setting characters. NBSP unit gaps are retained but are not the wrap-prevention mechanism: native annotation resize can leave text in HEIGHT mode with stale width. Own-resize writes restore natural width before recentering on the measured axis, preserving text orientation and its normal-axis top anchor (including the captured y=40 case); radius reflow retains the leader-side text edge. Root geometry and ownership are not changed by text reflow.
- On plugin open/current-page reconciliation, editable plugin H/V/edge-local/radius frames with constrained/truncated labels receive font-loaded, content-preserving reflow without remeasuring targets or rewriting label characters, fonts, styles, units/scale, metadata or saved pose baselines. Existing movement/resize tracking still applies independently, and the existing legacy axis-a upgrade remains a separate operation that can reframe roots as described below. All mixed font ranges are loaded before reflow. Session/page/close, revision, editability, root geometry and text snapshots guard asynchronous completion; normalization does not create a pending resize or ownership-detach loop. Locked/instance boundaries and unsupported roots are skipped. Tests model HEIGHT stale-width wrapping even at NBSP, longer resize digits, short-span overflow, horizontal/vertical/sloped/radius anchoring, captured 185:4730, mixed fonts/style/content preservation, static targets and cancellation. Font metrics and native resizing are simulations, not a live Figma-engine validation.
- Linear endpoint options are Slash (default), Arrow (open two-line V using the configured line color and weight), and Triangle (filled). Horizontal, vertical, and angled dimensions support all three; radius arrows remain filled triangles.
- Saved settings remain compatible: internal `slash` displays Slash, new `line-arrow` displays Arrow, and legacy `arrow` continues to render a filled Triangle. Initial hydration and UI updates use the same reversible mapping.
- Both Arrow and Triangle retain the horizontal -0.5px y correction and use a +0.5px x correction on vertical endpoints (local x = 3.5px). Open Arrow artwork is translated inward by `weight * hypot(6, 3) / (2 * 3)` so the visible MITER tip stops at the nominal measurement endpoint, including H/V, gaps, blanks, and angled dimensions. All three V points move together without changing the angle; native caps and MITER joins are retained. Triangle, Slash, radius arrows, measured spans, and labels are unchanged.

Static ownership and freeform annotations:
- Target/pair IDs exist only to replace the correct slots on an explicit annotation action. Moving, resizing, rotating, reparenting or deleting a target never redraws a permanent annotation. There is no target geometry watcher, rebuild queue or radius-specific refresh path.
- Independently moving/rotating or reparenting an annotation clears target and gap-pair ownership permanently. Detection compares its last saved parent-relative transform and parent identity, with only numerical tolerance (0.0001px translation, 0.0000001 matrix coefficients). Target drift is not considered. Moving a shared ancestor leaves local poses unchanged. Grouping an annotation with all its owners into a shared child group is recognized; other reparenting is treated as independent movement.
- Explicit re-annotation checks saved own poses before replacement, including moves made while closed or before a batched event arrives. A moved annotation remains freeform with its original root ID, pose, units, scale, style and geometry; a new annotation is created for the target. Moving it back or using Auto cannot reconnect it. Unmoved owned annotations remain eligible even after their targets move independently. There is no sibling-target fallback.
- Own resizing updates H/V and perimeter-edge labels from root width/height. Measured-axis resizing stretches only the dimension line and moves fixed-size endpoints; perpendicular resizing adjusts extension distance without changing the measurement, endpoint size, font size or stroke weight. Native K scales children/fonts/strokes itself; the observer only updates text, never applies a second artwork multiplier. Perimeter slots take priority over h/v side slots, so directional buttons cannot delete perimeter dimensions. Radius alone retains its existing SCALE artwork/reference model. This supersedes the former axis-a perimeter SCALE description.
- On plugin open and entry to a loaded page, editable legacy axis-a frames/components are conservatively upgraded in place; Update appearance of all also attempts/retries the upgrade before styling. Figma can reorder vectorPaths (including placing the last NONZERO slash before the NONE mainline); extraction now preserves subpath boundaries and requires a unique straight segment parallel to the label orientation. Witnesses are identified geometrically at each endpoint, never by flattened point indices. Ambiguous/unsupported geometry, invalid saved scale/units, mixed legacy fonts/paints, locked/instance boundaries and unavailable fonts are skipped with a notification, not guessed or deleted. Saved numeric label values are never scale evidence.
- Upgrade preserves the root ID, parent, relaunch data, font face/size, label orientation/center, line paint/weight, endpoint style, target/freeform ownership and perimeter key. It reframes the root to its exact current measured span while preserving mainline endpoints in parent coordinates; root size/transform can necessarily change to establish edge-local axes, without snapping back to the target. Existing witness starts and independently missing witnesses are retained. Slash geometry is normalized to the same native endpoint artwork as rectangle dimensions. Bulk styling after migration retains the new root pose/size and witness starts. Completed migration writes are baselined so they are not treated as user moves; independently moved legacy annotations detach before migration and survive Auto. A legacy annotation without a saved pose starts at its current pose because earlier movement cannot be attributed.
- Resize-label and legacy-upgrade font work is asynchronous and guarded by session/page/close, editability and current-geometry snapshots (resize labels also use revisions). The plugin only observes its current loaded page while open, never loads the whole document, and cannot update labels or migrate while closed. Failed upgrades are not retried on every event; explicit bulk appearance can retry. Deleted targets do not cause surviving annotations to crash.
- Actual Figma capture fixtures for 171:2484, 171:2475 and 171:2478 from latest9460a24d are stored in tests/legacy-axis-a.json, retaining path ordering, transforms, text orientation and missing witnesses. Their recovered mainline lengths are approximately 362.127172, 209.872838 and 227.956975px. Test metadata supplies units/scale explicitly because the original saved values are unknown. Regression tests exercise production migration/builders/observers, measured-axis-only then perpendicular-only resizing, repeated resizes, native-K simulation, all endpoint styles, slope/axis cases, target-static/freeform protection and async cancellation. Browser artifacts /tmp/opencode/architectural-resize-before-after.html and .png compare the captured geometry, production upgrade, and simulated normal resize. Mock fonts/constraints and browser SVG rendering are not real Figma resize evidence; a host-engine resize check remains required after deployment. No live canvas is modified by these tests.

Radius update request:
For circular objects, it would be great to annotate radius, rather than the outer shapes, can you research how it works in architectural drawings and do it that way? (while keeping the style of our annotations)

- Native circular ellipses and circular arcs receive one R-prefixed radius annotation instead of width/height bounding dimensions. Noncircular ellipses retain axis dimensions; arbitrary vector curves are not inferred to be circles.
- Uses a center-aligned radial leader, one inward-pointing arrow touching the curve, and an external horizontal landing with upright text. Retains configured font, size, line/font colors, line weight, units, precision, and scale. Slash endpoint preferences remain unchanged for linear dimensions.
- Auto selects the clearer quadrant; directional buttons explicitly replace the eligible owned radius callout. Existing owned bounding dimensions are replaced without duplicating the radius. Multi-selected circles participate in projected bounding-box gap measurements while retaining radius annotations rather than shared vertical dimensions.
- Radius annotations remain static on target movement, rotation, resize and arc edits. Explicit re-annotation measures the current circle/arc, or switches to axis dimensions for a genuine ellipse; moved freeform callouts are preserved.
